# پلتفرم جامع هشدار تقاطع EMA برای متاتریدر ۵

این پروژه یک راهکار حرفه‌ای و سطح تجاری (Enterprise-Grade) برای شناسایی تقاطع‌های میانگین متحرک نمایی (EMA) در متاتریدر ۵ و ارسال هشدارهای آنی از طریق چندین کانال ارتباطی است.

## ویژگی‌های کلیدی
*   **تشخیص دقیق سیگنال:** شناسایی تقاطع‌های طلایی (Golden Cross) و مرگ (Death Cross) بلافاصله پس از بسته شدن شمع.
*   **سیستم اطلاع‌رسانی چندگانه:** ارسال هشدار همزمان از طریق Push Notification، ایمیل و وب‌هوک.
*   **سرور اختصاصی پایتون:** دریافت وب‌هوک‌ها، ثبت در دیتابیس و ارسال پیامک (SMS).
*   **امنیت بالا:** احراز هویت درخواست‌ها با استفاده از API Key و Bearer Token.
*   **پایداری و عدم تکرار:** جلوگیری هوشمندانه از ارسال هشدارهای تکراری حتی پس از ریستارت شدن متاتریدر.
*   **لاگ‌گیری پیشرفته:** ثبت تمامی وقایع در فایل‌های CSV در متاتریدر و فایل‌های چرخشی در سرور.
*   **آماده برای استقرار:** دارای Dockerfile و Docker Compose برای نصب سریع در محیط‌های ابری.

## ساختار پروژه
پروژه از سه بخش اصلی تشکیل شده است:
۱. **MT5:** شامل اکسپرت ادوایزر و کتابخانه‌های MQL5.
۲. **Server:** شامل کدهای سمت سرور پایتون، تنظیمات داکر و دیتابیس.
۳. **Docs:** مستندات کامل فارسی شامل راهنمای نصب، تنظیمات و عیب‌یابی.

## شروع سریع
برای راه‌اندازی سریع سیستم، مراحل زیر را دنبال کنید:
۱. سرور پایتون را با استفاده از Docker Compose در پوشه `Server` اجرا کنید.
۲. اکسپرت را در متاتریدر ۵ کپی کرده و URL سرور و API Key را در تنظیمات آن وارد کنید.
۳. برای جزئیات بیشتر، به [راهنمای نصب](Docs/Installation.md) مراجعه فرمایید.

## تاریخچه تغییرات (Changelog)

### نسخه ۱.۲ (رفع باگ کامپایل + قابلیت تلگرام)
*   **رفع باگ بحرانی کامپایل:** تمام دسترسی‌های عضو (member access) روی پوینترهای اشیاء در MQL5 که به‌اشتباه با عملگر `->` (سبک ++C) نوشته شده بودند، به عملگر صحیح `.` (سبک MQL5) اصلاح شدند. این باگ باعث می‌شد کل پروژه اصلاً کامپایل نشود؛ اکنون با `0 errors, 0 warnings` کامپایل می‌شود.
*   **رفع باگ Import سرور:** ایمپورت‌های نسبی پایتون (`from .config import Config`) که فقط در حالت اجرای پکیجی کار می‌کردند، به ایمپورت مستقیم تغییر یافتند تا دستور مستند‌شده‌ی `python app.py` بدون خطا اجرا شود.
*   **رفع BOM:** بارگذاری فایل `.env` و پارس کردن بدنه‌ی JSON درخواست‌ها اکنون در برابر BOM (که Notepad ویندوز هنگام ذخیره‌ی UTF-8 اضافه می‌کند) مقاوم هستند.
*   **قابلیت جدید - نوتیفیکیشن تلگرام:** ارسال هشدار به یک چت/کانال تلگرام از طریق Bot API، کاملاً مستقل از SMS (فعال‌سازی با `ENABLE_TELEGRAM=True` در `.env`).
*   **آماده‌سازی برای تولید:** اضافه شدن `run_production_windows.py` (بر پایه‌ی `waitress`، سازگار با ویندوز، جایگزین سرور توسعه‌ی Flask) و راهنمای کامل استقرار روی VPS ویندوزی با NSSM در `Docs/Deployment.md`.

### نسخه ۱.۱ (بازبینی و اصلاحات)
پس از بازبینی فنی کامل پروژه، موارد زیر اصلاح شد:
*   **لاگ CSV:** خروجی CSV اکنون دقیقاً با ستون‌های `Date,Time,Symbol,Signal,Price,Push,Email,Webhook,Status` و یک ردیف هدر نوشته می‌شود (به‌جای یک رشته‌ی متنی ترکیبی).
*   **پاسخ API سرور:** ساختار پاسخ‌های موفق و ناموفق دقیقاً مطابق اسپک (`{"success": true/false, "message"/"error": ...}`) اصلاح شد و برای تمام خطاها (400/401/403/404/405/500) اعمال شد.
*   **مدیریت خطای Webhook:** کدهای HTTP مختلف (400/401/403/404/500) اکنون جداگانه شناسایی و لاگ می‌شوند؛ خطاهای شبکه‌ای/ترمینالی (Timeout، DNS، اتصال رد شد، عدم مجوز WebRequest) نیز جدا از خطاهای HTTP مدیریت می‌شوند. خطاهای 4xx دیگر تلاش مجدد (retry) نمی‌کنند چون نیاز به تغییر تنظیمات دارند نه شبکه.
*   **اعتبارسنجی ورودی اکسپرت:** بررسی می‌شود که `Fast EMA < Slow EMA`، دوره‌های EMA مثبت باشند، و در صورت فعال بودن Webhook، آدرس آن خالی نباشد؛ در غیر این صورت اکسپرت با پیام خطای فارسی از راه‌اندازی امتناع می‌کند (`INIT_FAILED`).
*   **مدیریت Handle نامعتبر:** ساخت اندیکاتور EMA (`iMA`) اکنون بررسی می‌شود؛ در صورت شکست، اکسپرت اجرا نمی‌شود.
*   **مستندات:** `Docs/MT5_Settings.md` و `Docs/Testing.md` با راهنمای گام‌به‌گام کامل (تنظیم MetaQuotes ID، SMTP جیمیل، لیست سفید WebRequest، و تست جداگانه هر کانال شامل Golden Cross و Death Cross) بازنویسی شدند.
